ScriptRunner is a free, open-source SQL script runner for PostgreSQL, SQL Server, MySQL, Oracle, DB2 and SQLite. Run scripts from an interactive console UI, from the command line in CI/CD pipelines, or directly from your own .NET programs, and generate a full schema create script from any live database.

A SQL script runner built for operational work

A lightweight framework to run scripts, manage execution context, and capture results for automation and operational tasks.

One-off or batched runs

Pick a scripts folder, choose the files you want, and run them in order. Use .sql files with GO batches, or .txt script lists that nest other lists.

Auditable results

Every statement's outcome is written to a timestamped run log, so every run leaves a record.

CI/CD ready command line

Pass the database type, connection string and folder (plus optional file names) to run with no prompts. Exit codes report success or failure to your pipeline.

Embeddable .NET library

Call SqlScriptRunner.RunAsync from your own app, service or test fixture. Same engine as the console app, with progress events and error callbacks.

Schema create scripts

Generate DDL for tables, views, functions, procedures and triggers from a live connection, built with each database's own reflection tools.

Optional data export

Add INSERT statements for every existing row alongside the generated schema, with values formatted by column type.

Remembers your settings

Connection strings and script folders are saved, so the next run is a couple of keypresses.

Supported databases

One SQL script runner for every database you work with, using each provider's native .NET data driver, whether you run it from the UI, the command line or your own code.

Quick start: run SQL scripts from the command line

Download a prebuilt Windows x64 or Linux x64 release, or build it yourself with the .NET 10 SDK.

1. Build

Requires the .NET 10 SDK.

git clone https://github.com/cccsdh/Dnp.ScriptRunner.git
cd Dnp.ScriptRunner
dotnet restore
dotnet build --configuration Release

2. Run interactively

ScriptRunner prompts you for the database type, the connection and the scripts to run.

dotnet run --project ./ScriptRunner/Dnp.ScriptRunner.csproj

3. Or run non-interactively from the command line

Supply the database type, connection string and scripts directory, optionally followed by the files to run. ScriptRunner never prompts, so CI/CD pipelines, scheduled jobs and other programs can start it as a process.

# <DatabaseType> "<ConnectionString>" "<ScriptsDirectory>" [file ...]
# Windows
dotnet run --project ./ScriptRunner/Dnp.ScriptRunner.csproj -- PostgreSQL "Host=localhost;Username=app;Password=pass;Database=mydb" "C:\scripts"
# Linux
dotnet run --project ./ScriptRunner/Dnp.ScriptRunner.csproj -- PostgreSQL "Host=localhost;Username=app;Password=pass;Database=mydb" "/home/me/scripts" 01_schema.sql release.txt
  • DatabaseType: one of PostgreSQL, SqlServer, Sqlite, MySQL, Oracle, DB2
  • ConnectionString: the full connection string for the provider (quote it if it contains spaces)
  • ScriptsDirectory: full path to the folder of .sql and .txt scripts
  • file ... (optional): specific scripts to run, in order. Without them, every script in the folder runs in name order.

The run stops at the first failed statement and exits with 0 on success, 1 on a failed statement, 2 for an unknown database type, 3 if the folder is missing and 5 on a fatal error such as a connection failure. The connection string and scripts directory are saved to Settings if they aren't already there.

Run SQL scripts from your own .NET code

The engine behind the UI and CLI is a class library, Dnp.ScriptRunner.Core, with no console dependency. Call it from an ASP.NET Core startup, a worker service, a deployment tool or an integration-test fixture.

using Dnp.ScriptRunner;

var result = await SqlScriptRunner.RunAsync(
    new ScriptRunOptions(DatabaseProvider.PostgreSQL, connectionString)
    {
        ScriptDirectory = "/srv/app/sql",
        OnError = failed => ScriptErrorAction.Stop,
        OnEvent = e => logger.LogInformation(e.Message)
    });

if (!result.Success)
    throw new Exception(result.Failures[0].Error);

// Inline SQL and schema scripts are one call each
await SqlScriptRunner.RunSqlAsync(options, "CREATE TABLE ...");
string ddl = SqlScriptRunner.GenerateSchemaScript(
    DatabaseProvider.SqlServer, connectionString, includeData: true);
  • Same six providers: PostgreSQL, SQL Server, MySQL, Oracle, DB2 and SQLite
  • Run a whole folder, an ordered file list, .txt script lists or an inline SQL string
  • Decide what happens on each failure: continue, skip the file or stop
  • Progress events and an optional TextWriter run log
  • A result object with counts, timings and every failed statement's SQL and error
  • Cancellation with a standard CancellationToken
  • Never prompts, and never writes files you didn't ask for
# Reference from source, or pack as a NuGet package
dotnet add reference ScriptRunner.Core/Dnp.ScriptRunner.Core.csproj
dotnet pack ScriptRunner.Core -c Release -o ./nupkg

Full API reference: ScriptRunner.Core README.

Generate a create script from an existing database

Point ScriptRunner at an existing database and get back a single .sql file that recreates it.

  1. After choosing a connection, answer Yes to “Generate a schema create script for this connection?”
  2. Choose whether to include data as INSERT statements for each table.
  3. Pick or create an output directory. It's created automatically if it doesn't exist.
  4. ScriptRunner writes schema-create-<DatabaseType>-<timestamp>.sql and exits. No scripts run in this mode.
  • CREATE SCHEMA statements for providers that have a schema concept
  • CREATE TABLE with columns, defaults, identity columns, keys, constraints and indexes
  • Views, functions, stored procedures and triggers
  • Optionally, an INSERT INTO for every existing row
ProviderSchema statementTable DDL sourceViews / functions / procedures / triggers
PostgreSQLCREATE SCHEMA IF NOT EXISTSinformation_schema + pg_constraint / pg_indexespg_get_viewdef, pg_get_functiondef, pg_get_triggerdef
SQL ServerGuarded CREATE SCHEMA (skipped for dbo)sys.columns + sys.key_constraints / sys.foreign_keys / sys.indexessys.sql_modules.definition, each object separated by GO
MySQLCREATE SCHEMA IF NOT EXISTS + USESHOW CREATE TABLESHOW CREATE VIEW / PROCEDURE / FUNCTION / TRIGGER
OracleNot applicable (schema is the connected user)DBMS_METADATA.GET_DDL('TABLE', ...)DBMS_METADATA.GET_DDL for each object type
DB2CREATE SCHEMASYSCAT.COLUMNS + SYSCAT.TABCONST / SYSCAT.REFERENCES / SYSCAT.INDEXESSYSCAT.VIEWS / SYSCAT.ROUTINES / SYSCAT.TRIGGERS
SQLiteNot applicableOriginal CREATE TABLE text from sqlite_masterRead from sqlite_master (SQLite has no procedures or functions)
Good to know
  • If one object can't be scripted, for example because of a permissions issue, a -- Failed to generate DDL for ... comment is written in its place and generation carries on.
  • SQL Server tables with an identity column are wrapped in SET IDENTITY_INSERT ... ON/OFF so existing key values are kept.
  • Data is scripted in schema order, not foreign-key dependency order. You may need to reorder statements or disable constraint checks when loading into a fresh database.

Frequently asked questions

How do I run SQL scripts from the command line?

Pass the database type, the connection string and the scripts directory, optionally followed by specific files, for example Dnp.ScriptRunner.exe PostgreSQL "Host=localhost;Database=mydb;..." "C:\scripts" on Windows, or ./Dnp.ScriptRunner PostgreSQL "Host=localhost;Database=mydb;..." "/home/me/scripts" on Linux. ScriptRunner runs without any prompts, stops at the first failed statement and returns a non-zero exit code on failure, which makes it suitable for CI/CD pipelines and for other programs that start it as a process.

Can I run SQL scripts from my own C# or .NET application?

Yes. The engine is a .NET class library, Dnp.ScriptRunner.Core, with no console dependency. Reference it and call SqlScriptRunner.RunAsync with a database provider, a connection string and a scripts folder or file list. You get progress events, a per-failure error callback (continue, skip the file or stop) and a result with every failed statement. RunSqlAsync runs inline SQL and GenerateSchemaScript returns a schema create script.

Can one tool run SQL scripts against several different databases?

Yes. ScriptRunner runs the same script folders and script lists against PostgreSQL, SQL Server, MySQL, Oracle, DB2 and SQLite using each database's native .NET driver, from the interactive UI, the command line or the .NET library.

Which databases does ScriptRunner support?

PostgreSQL, Microsoft SQL Server, MySQL, Oracle, IBM DB2 and SQLite.

How do I generate a CREATE script from an existing database?

In interactive mode, choose a connection and answer Yes to “Generate a schema create script for this connection?”. ScriptRunner writes a single .sql file containing CREATE SCHEMA, CREATE TABLE (with keys, constraints and indexes), views, functions, stored procedures and triggers, built with the database's own DDL reflection.

Can ScriptRunner export table data as INSERT statements?

Yes. When generating a schema create script you can choose to include an INSERT INTO statement for every existing row. Values are formatted by column type, and SQL Server identity columns are wrapped in SET IDENTITY_INSERT.

What types of script files can it run?

ScriptRunner runs .sql files (with optional GO batch separators) and .txt script lists that name other scripts or nest further lists with >>. Statements can embed JSON, XML or text files with <DnPJson>, <DnPXml> and <DnPTxt> tags. From the .NET library you can also run inline SQL strings.

Is ScriptRunner free?

Yes. ScriptRunner is open source under the MIT License. Prebuilt releases are available for Windows x64 and Linux x64 and need the .NET 10 runtime; you can also build it from source with the .NET 10 SDK.
